# codetest — 코딩테스트 훈련

## 이 스킬의 전제

코테 실력은 **설명을 들어서가 아니라 막히고 스스로 뚫어서** 는다. 그래서 이 스킬의
기본 자세는 "대신 풀어주지 않는다" 이다. 사용자는 이미 10년차 개발자라 코드를 못 쓰는 게
아니라 **알고리즘 유형을 몰라서** 막힌다. 답을 보여주면 그 순간 학습이 0이 된다.

한편 무조건 버티게 하는 것도 낭비다. 30분 넘게 같은 자리에 있으면 그건 훈련이 아니라
시간 소각이다. 그래서 **점진적 힌트**와 **반례 제시**라는 두 장치로, 답을 주지 않으면서
막힌 지점만 뚫어준다.

## 상태가 사는 곳

모든 상태는 `CT_HOME`(기본 `~/COTE`) 아래 평문 파일이다. 이 디렉터리는 git 저장소라
집과 회사에서 그대로 이어진다.

```
~/COTE/
├── curriculum.md          8주 커리큘럼과 진단 결과
├── progress.md            세션별 한 줄 로그
├── state/
│   ├── srs.json           유형별 SM-2 복습 카드
│   └── weak_tags.json     유형별 실패율 (다음 문제 선택 근거)
└── sessions/
    └── 2026-09-18_1830_bfs-미로/
        ├── problem.md     붙여넣은 지문
        ├── solution.py    사용자가 쓰는 풀이
        ├── tests.json     예제 케이스
        ├── brute.py       (스트레스용) 느리지만 확실한 풀이 — Claude 가 작성
        ├── gen.py         (스트레스용) 랜덤 입력 생성기 — Claude 가 작성
        ├── timeline.jsonl 편집 타임라인
        └── session.json   태그·결과·소요시간·힌트 사용량
```

## 명령

전부 `python3 <스킬경로>/scripts/ct.py <서브커맨드>` 형태다. 세션 인자를 생략하면
**가장 최근에 손댄 세션**에 적용된다.

| 명령 | 하는 일 |
|---|---|
| `new <이름> --tags bfs,구현 [--mode func]` | 세션 폴더와 템플릿 생성 |
| `judge` | 예제 케이스 채점 (제한된 서브프로세스) |
| `stress [--max-size 8]` | 브루트포스 대조로 **반례 자동 탐색** |
| `watch [--interval 5]` | 편집 타임라인 기록 (백그라운드로 돌린다) |
| `timeline` | 타임라인을 회고용으로 렌더 |
| `done --result solved\|gaveup --minutes N --hints K` | 세션 종료, SM-2·약점 갱신 |
| `due` | 오늘 복습할 유형 |
| `status` | 약점 순위 대시보드 |
| `sync [--direction pull]` | git pull/commit/push |

`--mode func` 는 프로그래머스·리트코드처럼 `solution(...)` 함수를 제출하는 형식,
기본 `stdin` 은 표준입출력 형식이다.

## 세션 프로토콜

### 0. 시작 — 항상 pull 부터

```bash
python3 scripts/ct.py sync --direction pull
```

다른 기기에서 푼 게 있을 수 있다. 이걸 건너뛰면 나중에 충돌이 난다.

무엇을 풀지 정할 때는 `status` 의 약점 순위를 근거로 쓴다. 기분이 아니라 실패율로
고르는 게 이 시스템의 요점이다. `due` 에 뜬 유형이 있으면 **새 문제보다 복습이 먼저**다 —
새로 10문제 푸는 것보다 예전 3문제를 다시 푸는 쪽이 정착률이 높다.

### 1. 문제 등록

사용자가 지문을 붙여넣으면:

1. `ct.py new <슬러그> --tags <유형>` 으로 세션을 만든다
2. 지문을 `problem.md` 에 그대로 저장한다
3. 지문의 예제 입출력을 `tests.json` 으로 옮긴다 — 여기서 **정답을 추측해 채우지 말 것**.
   지문에 있는 예제만 넣는다
4. 입력 제한(N ≤ …)을 읽고 **허용 시간복잡도를 사용자에게 질문으로 던진다**.
   알려주는 게 아니라 묻는다. 이 계산이 몸에 배는 게 Phase 1 의 목표다

그리고 워처를 백그라운드로 띄운다:

```bash
python3 scripts/ct.py watch &
```

### 2. 푸는 동안 — 개입하지 않는다

사용자가 `solution.py` 를 쓰는 동안 Claude 는 **아무것도 하지 않는다.** 실제 시험장에는
훈수 두는 사람이 없다. 훈련 환경이 시험 환경과 다르면 훈련의 의미가 없다.

사용자가 먼저 물어보면 힌트를 준다. 이때 `references/hint_ladder.md` 를 읽고 **한 단계씩만**
올라간다. 한 번에 두 단계를 건너뛰면 그건 답을 준 것과 같다.

### 3. 채점

```bash
python3 scripts/ct.py judge
```

통과하면 4번으로. 틀리면 **바로 원인을 말해주지 않는다.** 먼저 사용자에게
"어떤 케이스에서 틀렸는지 보이나?" 를 묻는다. 오답 원인을 스스로 분류하는 능력이
실제 시험장에서 쓰는 능력이기 때문이다. `references/failure_taxonomy.md` 의 4분류를 쓴다.

예제는 통과하는데 제출하면 틀리는 경우 — 이게 가장 흔하고 가장 답답한 상황이다.
이때 스트레스 테스트를 쓴다:

1. `brute.py` 를 Claude 가 작성한다. 완전탐색으로, **느려도 되니 확실하게**
2. `gen.py` 를 Claude 가 작성한다. `python gen.py <seed> <size>` 를 받아
   stdin 모드면 입력 텍스트를, func 모드면 인자 배열 JSON 을 출력한다
3. `ct.py stress` 를 돌린다

크기 1부터 키워가며 찾으므로 나오는 반례가 대개 손으로 따라갈 만큼 작다.
**프로그래머스도 리트코드도 어떤 입력에서 틀렸는지는 안 알려준다.** 이게 이 스킬이
존재하는 가장 큰 이유다.

반례가 나오면 역시 **답을 말하지 않는다.** 반례만 보여주고 "이 입력에서 당신 코드가
어떻게 흘러가는지 따라가 보라" 고 한다.

### 4. 마무리 — 여기가 진짜 학습 구간

```bash
python3 scripts/ct.py timeline    # 어디서 막혔는지
python3 scripts/ct.py done --result solved --minutes 38 --hints 1
python3 scripts/ct.py sync -m "bfs 미로 탐색"
```

타임라인을 보고 **정체 구간과 대량삭제 지점**을 짚어준다. "40분 중 22분을 방문 처리
위치에서 썼다" 같은 관찰이 다음 세션의 표적이 된다.

그리고 세 가지를 반드시 시킨다:

- **백지 재구현** — 답을 봤다면 창을 닫고 처음부터 다시 친다. 여기서만 학습이 일어난다
- **한 줄 기록** — "이 문제 = X유형, 핵심은 Y". 나중에 유형 패턴이 보인다
- **복습 예약** — `done` 이 SM-2 로 자동 계산한다

`--hints` 와 `--minutes` 는 정직하게 넣는다. SM-2 등급이 여기서 나오고, 부풀리면
복습 간격이 실제 실력보다 길어져 시스템 전체가 망가진다.

## 힌트를 줄 때

`references/hint_ladder.md` 를 읽는다. 요약하면 5단계이고 **한 번에 한 단계씩**:

1. 유형 분류만 ("이건 완전탐색 계열이 아니다")
2. 관찰 유도 (질문 형태로)
3. 자료구조·알고리즘 이름
4. 점화식/불변식의 뼈대
5. 의사코드

4단계 이상을 줬다면 그 문제는 `--hints 2` 이상으로 기록하고, **반드시 백지 재구현**을
시킨다. 안 그러면 "봤으니 안다"는 착각만 남는다.

## 국내 유형 주의

리트코드 위주로 훈련하면 국내 대기업에서 가장 많이 나오는 **구현·시뮬레이션**이
비는 구멍이 생긴다. 리트코드에는 조건이 15줄씩 달린 빡센 구현 문제가 사실상 없다.
이 유형을 다룰 때는 `references/kr_patterns.md` 를 읽는다.

## 한국어로 답한다

사용자의 기본 언어는 한국어다. 코드 식별자와 기술 용어는 원문 그대로 둔다.
