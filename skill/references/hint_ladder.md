# 점진 힌트 5단계

**원칙: 한 번에 한 단계.** 사용자가 "더" 라고 할 때만 올라간다.
두 단계를 건너뛰면 답을 준 것과 같고, 그 순간 그 문제의 학습 가치는 0이 된다.

단계를 올리기 전에 항상 먼저 묻는다: **"지금까지 뭘 시도해봤나?"**
이 질문만으로 사용자가 스스로 뚫는 경우가 많다. 그게 제일 좋은 결과다.

---

## 1단계 — 유형의 울타리

무엇인지 말하지 않고 **무엇이 아닌지**만 말한다.

> "N이 10만이면 O(N²)는 안 된다. 지금 접근이 몇 번 도는지 세어봤나?"
> "이건 그리디로 보이지만 반례가 있다. 정렬 후 탐욕이 왜 깨지는지 생각해보라."

## 2단계 — 관찰 유도 (질문만)

답을 서술하지 않고 질문으로 시선을 옮긴다.

> "격자에서 최단 거리를 구할 때 DFS로는 왜 안 되나?"
> "같은 칸을 두 번 방문하면 무슨 일이 생기나?"
> "입력이 정렬되어 있다는 조건은 왜 줬을까?"

## 3단계 — 도구 이름

자료구조나 알고리즘의 **이름만** 준다. 쓰는 방법은 주지 않는다.

> "BFS와 큐를 쓴다."
> "값이 아니라 답을 이분탐색한다. 파라메트릭 서치라고 부른다."
> "유니온 파인드."

## 4단계 — 뼈대

점화식이나 불변식의 **형태**만 준다. 구현은 사용자 몫이다.

> "dp[i] = i번째까지 봤을 때의 최댓값. 전이는 두 가지 선택지 중 max."
> "방문 배열이 2차원이 아니라 3차원이어야 한다. 세 번째 축이 무엇일지 생각해보라."
> "while low < high 로 두고, 조건을 만족하면 high = mid, 아니면 low = mid + 1."

## 5단계 — 의사코드

여기까지 왔으면 **완성된 파이썬 코드는 절대 주지 않는다.**
의사코드까지만 주고, 코드는 사용자가 친다. 그리고 `--hints 3` 이상으로 기록한 뒤
**반드시 백지 재구현**을 시킨다.

```
q = deque([(시작, 0)])
visited[시작] = True
while q:
    현재, 거리 = q.popleft()
    if 현재 == 목표: return 거리
    for 다음 in 인접(현재):
        if 유효하고 미방문:
            visited[다음] = True
            q.append((다음, 거리+1))
```

---

## 힌트 대신 반례가 나은 경우

코드는 다 짰는데 틀리는 상황이라면 힌트 사다리를 올라가지 말고 **스트레스 테스트**로
반례를 찾아 보여준다. 반례는 답이 아니라 데이터라서, 사용자가 직접 추적해야만
원인이 나온다. 학습 효율이 힌트보다 높다.
