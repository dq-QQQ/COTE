# 오답 4분류

틀렸을 때 **원인을 분류하는 것**이 고치는 것보다 중요하다. 같은 유형의 실수가
반복되는지는 분류를 해야만 보이고, 실제 시험장에서 쓰는 능력도 이 분류 능력이다.

채점 결과를 보여준 뒤, 고치는 법을 알려주기 전에 먼저 묻는다:
**"넷 중 어느 쪽인 것 같나?"**

| 분류 | 증상 | 진짜 원인 | 다음 행동 |
|---|---|---|---|
| **시간초과** | 예제는 맞는데 제출하면 TLE | 시간복잡도 오판 | 입력 제한 → 허용 복잡도 역산을 **다시** |
| **논리오류** | 일부 케이스만 틀림 | 알고리즘 자체가 틀림 | 스트레스 테스트로 반례 확보 |
| **엣지케이스** | 대부분 맞고 한둘 틀림 | 경계 조건 누락 | 아래 체크리스트 |
| **입출력** | 답은 맞는데 형식이 틀림 | 출력 형식·자료형 | 지문의 출력 형식 재확인 |

---

## 시간초과

가장 많이 나오는 원인은 **알고리즘이 아니라 파이썬 관용구**다.

- `list.pop(0)` → O(n). `collections.deque` 의 `popleft()` 를 쓴다
- 문자열 `+=` 반복 → O(n²). `''.join(리스트)`
- `in` 을 리스트에 → O(n). `set` 으로 바꾸면 O(1)
- 재귀 DFS 깊이 초과 → `sys.setrecursionlimit`, 혹은 스택으로 전환
- `input()` → `sys.stdin.readline` (표준입출력 문제에서만 해당)

이걸 다 확인했는데도 느리면 그때 알고리즘을 의심한다.

## 엣지케이스 체크리스트

제출 전 30초만 훑는다. 이 목록으로 잡히는 오답이 전체의 상당수다.

- N = 1, 빈 입력, 원소 1개
- 전부 같은 값 / 전부 음수 / 0 포함
- 최댓값·최솟값 경계 (제한의 정확히 위아래)
- 중복 원소 허용 여부
- 답이 없는 경우 (-1 출력? 빈 배열?)
- 시작점 == 도착점
- 정렬이 이미 되어 있는 / 역순인 입력

## 논리오류

여기서 눈으로 코드를 노려보는 건 시간 낭비다. **스트레스 테스트가 압도적으로 빠르다.**
브루트포스와 랜덤 입력 생성기를 만들어 `ct.py stress` 를 돌린다.
